# 페르소나 인계

아이스브레이킹이 능력치를 만들고, 그다음 게임들이 받아 씁니다. **만드는 쪽이
스키마의 원본**이므로 능력치는 자기 이름 그대로 나가고, 받는 쪽이 자기 규칙에
맞춰 매핑합니다.

## 내보내는 것

```
GET /rooms/{code}/persona
```

방이 `DONE`이고 리포트가 한 번이라도 조회된 뒤에 200을 냅니다. 리포트를 만드는
시점에 능력치가 저장되므로, 리포트를 먼저 열어야 합니다.

```json
{
  "session_id": "...",
  "scale": 100,
  "players": [
    {
      "playerId": "0b7f...",
      "nickname": "종훈",
      "personaScores": { "DOM": 42, "SPD": 76, "EXP": 38, "EMP": 64, "OBS": 82 }
    }
  ]
}
```

- **0~100 정수**입니다. 내부 능력치는 0.0~5.0이고 내보낼 때 `×20` 합니다.
  변환은 경계에서 한 번만 하고, 양쪽 로직에는 안 들어갑니다
- `players[].playerId` / `players[].personaScores`는 **마피아 쪽이 이미 받는 모양**과
  같습니다. 이 응답을 그대로 `POST /mafia/rooms/{id}/persona`에 넘길 수 있습니다
- 실려 나가는 값은 **`BEHAVIOR` 출처뿐**입니다. 첫인상 투표에서 나온
  `IMPRESSION_PRE` / `IMPRESSION_POST`는 레이더 점선 전용이라 넘기지 않습니다

## 다섯 축

| 코드 | 이름 | 무엇을 재나 |
|---|---|---|
| `DOM` | 주도력 | 판을 먼저 벌리나 |
| `SPD` | 순발력 | 얼마나 빨리 결정하나 |
| `EXP` | 표현력 | 자기를 얼마나 드러내나 |
| `EMP` | 공감력 | 남을 얼마나 살피나 |
| `OBS` | 관찰력 | 남을 얼마나 맞히나 |

## 마피아 쪽에서 바꿀 것

지금 `PERSONA_AXES = ("initiative", "analysis", "empathy", "caution")` 인데,
넷 중 셋이 우리 축과 거의 1:1입니다.

| 지금 | 바꿀 것 | 비고 |
|---|---|---|
| `initiative` | `DOM` | 사실상 같은 것 |
| `analysis` | `OBS` | 남을 읽는 능력 |
| `empathy` | `EMP` | 같은 것 |
| `caution` | `100 - SPD` | 신중함은 순발력의 반대 |
| — | `EXP` | 새로 씀 |

**바꿀 파일 넷**

| 파일 | 무엇을 |
|---|---|
| `models/persona.py` | 필드 이름 넷 → 다섯 |
| `roles/weights.py` | 가중치 딕셔너리 셋 |
| `roles/assignment.py` | `players[pid].empathy` 타이브레이크 한 줄 |
| `persona/provider.py` | `PERSONA_AXES` 참조 |

`PersonaScores.from_partial()`이 빠진 축을 중립 50으로 채우게 돼 있어서, 축이
늘어도 기존 호출부는 안 깨집니다.

### 가중치 제안

`EXP 표현력`이 마피아에 잘 맞습니다. **말 많은 사람이 마피아면 티가 나기** 때문에,
표현력이 낮은 쪽이 마피아가 되면 배정이 더 그럴듯해집니다.

```python
_MAFIA_WEIGHTS  = {"DOM": 0.30, "EMP_inverse": 0.25, "SPD_inverse": 0.20, "EXP_inverse": 0.25}
_POLICE_WEIGHTS = {"OBS": 0.60, "SPD_inverse": 0.40}
_DOCTOR_WEIGHTS = {"EMP": 0.65, "SPD_inverse": 0.35}
```

기존 구조를 그대로 두고 이름과 항목만 바꾼 형태입니다. 비율은 조정하셔도 됩니다.
